## 남은 문제와 제출 시 표현

1. **내비 출발 위치와 지도 렌더링.** 새 Pleos AVD의 내비 출발점은 성남으로 나타나며 약 270km가 표시됐습니다. 내비의 지도 배경이 검게 보이는 현상도 있었습니다. arrive의 지도는 정상입니다. 목적지 전달과 현장 경로 검증을 구분합니다. 시연은 arrive의 추천 화면을 중심으로 보여주고, 내비 구간은 목적지 전달의 증거로만 사용합니다.
2. **실제 휴대폰 확인.** 운영 연동은 데스크톱 모바일 크기 브라우저로 검증했습니다. 사용자가 실제 카메라 → Safari/Chrome → 합류까지 한 번 확인해야 합니다.
3. **장소 범위.** generic UI와 장소 데이터 구조가 있어도 현재 연결된 장소는 오룡관 한 곳입니다. 장소 검색·선택과 여러 카탈로그 전환을 지원한다고 소개하지 않습니다.
4. **추천 기준.** 실시간 빈자리·AI 순위·거리 최적화가 아닙니다. 방문 중 제외한 후보를 기억하고 등록 순서에서 다음 후보를 고릅니다. 다음 후보의 실제 주차 가능 여부는 보장하지 않습니다.
5. **현장 정보.** 진입구·하차 허용·일방통행·이용 자격·보행 동선은 현장 검수 전입니다. release에서도 추정 위치 길안내는 에뮬레이터에서만 허용합니다.
6. **제출 경로.** 최신 코드·release 빌드 설정·문서는 GitHub로 제출하고, APK·영상은 사용자의 개인 드라이브 링크로 별도 제출합니다. 최종 소스 해시는 push 완료 후 원격 main과 대조합니다. GitHub 공개 전환·드라이브 업로드·접수 발송은 사용자 작업입니다. `output/` 및 서명키는 계속 Git에서 제외합니다.

## 심사 관점에서의 판단

- 차량 특화성: 내비 목적지 전달, 차량 위치·기어·주행 제한, 주차 후 휴대폰 연결이라는 구체적 근거가 있습니다. 사용한 표준 Android Automotive API를 Pleos Vehicle SDK라고 표현하지 않습니다.
- 창의성: 주차장 목록만으로는 차별성이 약합니다. **주차 실패의 기록을 유지하고 다음 후보를 선택한 뒤 동승자의 입장·운전자의 합류까지 이어주는 경험**이 중심이어야 합니다.
- 기술 활용성: SDK 호출 자체보다 실제 목적지 전달과 확인, 화면 이탈 중 관측, 권한이 다른 웹 연결을 보여주는 편이 설득력 있습니다.
- 사업성: 현재 가장 약한 부분입니다. 실제 사용자 검증·제휴·사용량·매출이 없습니다. 시설의 검수 데이터로 초기 효용을 만들고 행사 안내에서 유입시키겠다는 가설과 검증 지표를 제시했습니다. 수상 가능성을 점수로 단정할 근거는 없습니다.

추가 기능을 급하게 늘리기보다, 다음 후보 자동 선택 장면과 현재 구현 범위를 정확히 설명하는 것이 이번 제출의 우선순위입니다.
