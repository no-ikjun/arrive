# 내비 복귀 · 운전자 휴대폰 이어가기

2026-11-14. 전체 흐름 점검의 우선순위 1번과 2번 후속 구현.

후속 인계: 다른 AI가 NestJS handoff API와 `0001_handoff_tokens.sql`을 구현했고 50개 백엔드 테스트/빌드가 통과했다. 아래 모의 서버 기록은 당시 검증이며 운영 배포 성공과 구분한다. 현재 k3s 배포는 미적용 마이그레이션이 있으면 중단하므로 DB 적용 여부를 먼저 확인해야 한다.

## 현재 상태

| 항목 | 구현 / 확인 | 운영 반영 |
| --- | --- | --- |
| 내비 사용 중 하차·주차 도착 제안 | 실제 Pleos SDK + 가상 GPS + P 상태로 확인 | 최신 debug APK를 에뮬레이터에 설치함 |
| 알림함에서 arrive 복귀 | 진행 상태 알림을 눌러 기존 단계로 복귀 확인 | 앱에 포함 |
| 주차 후 위치 관측 종료 | 주차 완료 뒤 ArrivalMonitorService 종료 확인 | 앱에 포함 |
| 주차 후 운전자 QR | 주차 완료 후 자동 표시, 별도 handoff 토큰 발급 | 백엔드 API 배포 필요 |
| 휴대폰 입구 안내 / 합류 확인 | 모의 서버에서 차량 QR → 모바일 웹 → 합류 → 차량 동기화 확인 | 백엔드 + Pages 최신 코드 배포 필요 |

이번 작업에서 백엔드 코드는 수정하지 않았고 원격 코드 push/Pages 배포도 실행하지 않았다. 휴대폰 쓰기 기능의 운영 검증 완료로 해석하면 안 된다.

## 사용자 작업 순서

1. **Claude에게 [CLAUDE_CONTINUITY_BACKEND.md](CLAUDE_CONTINUITY_BACKEND.md)를 전달한다.** 토큰 발급, 휴대폰 조회, 합류 확인 API 세 가지를 기존 NestJS 서버에 추가하고 테스트·운영 배포까지 요청한다. 차량 도착 감지에는 추가 API가 없다.
2. **백엔드 준비 후 웹 변경을 배포한다.** 단일 레포를 유지한다. `companion/` 변경이 GitHub의 배포 브랜치에 반영되고 Cloudflare Pages가 그 최신 커밋을 배포해야 한다. 기존 Root=`companion`, Build=`exit 0`, Output=`public`, `API_BASE_URL=https://arrive-api.ikjun.com` 설정을 유지한다. 추가 환경변수/도메인/공개 레포 전환은 필요 없다. `proxy-policy.mjs`, `public/handoff.js` 등 새 파일도 누락하지 않는다. 현재 작업 트리에는 이전 작업이 함께 있으므로 검토 후 커밋한다.
3. **차량 권한을 확인한다.** 다른 에뮬레이터/기기는 ‘더 보기 → 알림·위치 허용’. 차량 위치, Android 위치, 알림 권한과 시스템 위치 설정이 필요하다. 이번 에뮬레이터에서는 허용했다. 거절해도 수동 진행은 가능하지만 내비 뒤에서의 도착 알림은 사용할 수 없다.
4. **운영 배포 완료를 알려준다.** 실제 운영 토큰으로 전체 흐름을 다시 검증한다. 현장에서는 주차 완료 직후, 차에서 내리기 전에 운전자 본인 휴대폰으로 QR을 스캔한다. 입구 안내를 보고 실제로 동승자를 만난 뒤 ‘합류 확인 → 만났어요’를 누른다. 기존 동승자 QR에는 완료 권한이 없다.

현재 에뮬레이터 APK 주소는 `https://arrive-api.ikjun.com`, `https://arrive.ikjun.com`이다. 테스트 전 원래 방문 상태(주차장 1로 이동 중)를 복원했다. 모의 서버는 실제 API를 호출하지 않았다.

## 구현 동작

- 화면에서 방문 시작/하차 확인/주차장 변경을 저장한 다음 위치 foreground service를 시작하고 내비로 넘긴다. 서비스와 화면은 하나의 Pleos 위치/AAOS 변속 연결을 공유한다.
- 내비 뒤에서도 기존 45m 접근 / P 6초 유지 조건을 적용한다. 자동으로 하차·주차·합류를 확정하거나 화면을 강제로 전환하지 않는다.
- 도착 제안은 방문/단계/주차장별 한 번 알린다. 계속 표시되는 상태 알림은 알림함에서 복귀하는 용도이며, 하차·주차 도착 알림은 내비 유형으로 별도 표시한다. 이전 단계의 도착 알림은 단계가 바뀌면 지운다.
- 주차 확인, 방문 종료, 알림 끄기, 권한 회수, 최대 2시간에서 서비스를 종료한다. 알림을 끄더라도 방문 자체는 유지되며 다시 앱을 열면 진행 중인 방문의 관측을 재개한다. 앱 강제 종료/재부팅 후 자동 시작하지 않는다.
- 주차 후 QR은 ownerToken을 넘기지 않는다. 기존 암호화 저장소에 별도 handoff 토큰과 발급 재시도 키를 보관한다. 서버 반영이 끝난 주차 단계에서만 발급한다.
- 웹은 공유 링크와 운전자 연결을 분리한다. 서버가 부여한 합류 권한과 유효기간을 확인하고 실제 사용자 확인 후에만 완료를 요청한다. 응답 유실 시 완료를 추정하지 않으며, 같은 키 재시도 또는 GET 재조회로 상태를 확인한다. 완료 후 큰 안내를 ‘함께 도착했어요’로 전환한다.
- 프록시의 신규 쓰기는 합류 한 경로만 허용한다. 조회 토큰의 쓰기 거부와 토큰별 권한 검사는 NestJS 서버에서 반드시 수행해야 한다.

## 검증 기록

- Android `:app:assembleDebug`, `:app:lintDebug`, `:domain:test` 통과. 도메인 테스트 29개. 기존 lint 경고는 유지.
- `node --test companion/test/*.test.mjs`: 23개 통과. 권한별 UI, 만료, 재시도 키/원래 revision 유지, 임의 쓰기·잘못된 본문·다른 origin 차단, 쿠키 미전파, redirect 거부, 로컬/Pages 프록시 검증 포함.
- Wrangler Pages Functions 번들 생성 성공. 이는 실제 서버 연결/운영 배포 검증을 대신하지 않는다.
- 실제 Pleos Connect 2.1.0: 내비 전면 상태에서 위치/변속 관측 유지 및 도착 알림 확인. 알림함에 남는 ‘arrive · 방문 진행 중’을 눌러 하차 확인 화면으로 복귀. 기존 단계 유지, 복귀 자체로 경로 요청하지 않음.
- 모의 API + 실제 앱/브라우저: 시작 → 하차 확인 → 주차 확인 → QR 자동 표시 → QR 해독 → 390×844 모바일 지도/입구 안내 → 합류 확인. 차량도 REUNITED 반영.
- 모의 서버가 합류를 처리한 직후 HTTP 응답을 브라우저에서 끊음. 웹은 재조회로 REUNITED 복구, 서버 revision=5 / 합류 처리 횟수=1. 새로고침 후 상태 유지. 이때 발생한 네트워크 오류는 의도적인 테스트다.
- 조회용 share 토큰의 합류 POST가 모의 서버에서 403인 것과, 주차 완료 상태의 조회 링크 화면에 합류 버튼이 없는 것을 확인. 실제 API의 동일 보장은 Claude 테스트 필요.
- 마지막 ‘도착 알림 끄기’ UI 자동화는 화면 전환과 터치가 겹쳐 주차 확인을 눌렀으므로 통과로 기록하지 않는다. 앱이 새 공유 방문을 생성한 상태는 별도로 보존했고, 차량은 기존 로컬 방문의 주차장 1 이동 단계로 복원했다. 새 테스트 공유 방문은 삭제하지 않았으며 만료 시각은 2026-11-15 02:29 KST다. 기존 공유 방문에 완료 이벤트를 보내지 않았다. 복원용 임시 코드는 제거하고 최종 APK를 다시 빌드·설치했다.
- 화면: `output/playwright/continuity/01-notification-return.png`, `02-phone-qr.png`, `03-phone-guide.png`, `04-reunited-phone.png`, `05-reunited-car.png`.

## 남아 있는 한계

- 실제 운영 handoff API와 휴대폰 카메라/외부 지도 앱 전환은 배포 후 확인해야 한다.
- 내비 시작 위치가 가상 GPS와 일치하지 않았던 이전 시연 문제는 이번 수정 범위에 포함하지 않았다. 캠퍼스 도착 상황 재생과 실제 길안내 출발 위치를 구분해서 시연한다.
- 입구와 주차 핀은 추정값이며 검증된 보행 경로가 아니다. 남측 입구 사진과 실제 보행 동선 확인은 다음 개선 작업이다.
- 알림의 배치/팝업은 차량 시스템 설정에 따라 달라진다. Pleos 에뮬레이터에서의 확인을 모든 실차 환경에 대한 보장으로 확대하지 않는다.
