## 사용자가 직접 할 일 — 이 순서로

1. **지원서 검토·개인정보 입력.** 첫 페이지에서 개인/팀, 참가 부문, 성명, 연락처, 인원, 작성일을 채우고 참가 구성원 표도 작성합니다. 기획 본문의 표현이 의도와 맞는지 확인합니다. 심사용 본문에는 성명·소속·연락처를 추가하지 않습니다.
2. **동의서 확인·서명.** 마지막 페이지의 대표자 칸에 본인이 동의 여부, 성명, 서명, 날짜를 직접 기입합니다. 서명 이미지 또는 전자서명이 허용됩니다. 서명 후 DOCX 또는 PDF로 저장하고 페이지 누락을 확인합니다.
3. **실제 휴대폰으로 한 번 확인.** 에뮬레이터에서 새 방문 → 하차 확인 → 자리 없어요 → 다음 후보 → 주차 완료 → 운전자 휴대폰 안내 QR 스캔 → 입구 확인 → 합류 확인. QR은 방문마다 새로 만들고, 웹 주소만 직접 열지 않습니다. 동승자 조회 링크에는 합류 쓰기 권한이 없는 것이 정상입니다. QR 카메라·실제 Safari/Chrome은 사용자의 휴대폰에서 최종 확인해야 합니다. 기존 debug 앱과 release의 서명이 달라 덮어 설치가 안 됩니다. 별도 AVD를 쓰거나 기존 방문을 마친 뒤 앱 제거·재설치가 필요합니다.
4. **영상 검토.** 제공 영상의 핵심은 다음 후보 자동 선택입니다. 현장 주행·실시간 빈자리 감지로 설명하지 않습니다. 직접 설명을 녹음한다면 DEMO_SCRIPT를 사용합니다. 별도 라이브 촬영에서는 내비 기본 출발 위치가 성남으로 나타날 수 있으므로 캠퍼스 주행 시간처럼 설명하지 않습니다.
5. **GitHub 최종본 확인·공개.** 저장소 주소는 https://github.com/no-ikjun/arrive 입니다. 최신 소스와 문서의 push 완료 후 원격 main의 최종 커밋 해시를 확인합니다. APK와 영상은 개인 드라이브에 별도 업로드하고 다운로드 주소를 확정합니다. 두 파일이 들어 있는 `output/`은 Git에서 제외된 상태로 유지합니다. 공개 전환은 사용자가 진행합니다. 로그인하지 않은 창에서 저장소·APK·영상이 열리는지 확인합니다. `output/submission/private/`, `.env.local`, 서명키, 비밀번호, 방문 토큰/QR 원본은 올리지 않습니다. 공개 전환은 과거 이력도 공개하므로 이력의 비밀값 노출 여부도 별도로 확인합니다.
6. **접수 메일 발송.** 2026년 11월 15일 23:59 한국시간까지 `appdevchallenge@hyundai-partners.com`으로 보냅니다. 제목은 `[차량용 앱 개발 공모전] 성명_성명`(개인 참가). 서명한 지원서, GitHub 주소, 최종 커밋 해시, APK·영상 다운로드 주소를 넣습니다. APK명은 `참가자명_arrive_release.apk`로 변경합니다. 개인 드라이브의 APK·영상 링크는 로그인 없이 열고 다운로드할 수 있는지 확인합니다. 발송 후 보낸 편지함과 수신 확인을 확인합니다.
7. **심사 기간 유지.** 공식 공지상 GitHub는 11월 16일까지 공개하고 11월 23일까지 유지합니다. API·동승자 웹도 심사자가 실행할 수 있도록 유지합니다. 서명키와 비밀번호는 비공개로 백업합니다.
