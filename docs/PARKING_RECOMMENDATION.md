# 다음 주차장 추천

2026-11-15 구현. 이 문서는 현재 구현과 제출 시연의 표현 범위를 정리합니다.

## 핵심 경험

목적지에 도착했지만 주차할 곳이 없을 때, 운전자가 다음 후보를 다시 검색하고 고르는 수고를 줄입니다. 동승자는 먼저 건물에 들어가고 운전자는 주차 후 같은 입구로 합류합니다.

1. 현재 후보를 공통 P 아이콘과 실제 주차장 이름으로 표시합니다.
2. 운전자가 **자리 없어요**를 누르면 해당 후보를 이번 방문에서 제외합니다.
3. 등록된 순서에서 아직 제외하지 않은 다음 후보를 자동 선택합니다.
4. **다음 주차장을 추천했어요** 카드, 제외 수, 지도 핀을 동시에 갱신합니다.
5. **이곳으로 길안내**를 누르면 Pleos 내비게이션에 선택한 후보의 좌표를 전달합니다.
6. 주차 완료 후 기존 휴대폰 입구 안내·합류 확인으로 이어집니다.

이전 UI는 후보 변경 직후 내비게이션이 전면으로 나와 추천 결과를 보기 어려웠습니다. 이번에는 추천 결과를 화면에 유지합니다. 후보를 선택하는 터치는 필요 없지만, 길안내 시작에는 확인 터치 한 번이 필요합니다. 별도 카운트다운이나 화면 재진입에 따른 자동 길안내는 없습니다. 최초 하차 후 주차 안내 연결은 기존 동작을 유지합니다.

## 시연 순서

- 오룡관 방문 시작, 동승자 하차 확인 후 arrive 화면으로 복귀합니다.
- 주차장 1에서 **자리 없어요** → 제외 수가 늘고 주차장 2가 추천되는 모습을 보여줍니다.
- 다시 **자리 없어요** → 이번 방문에서 2곳 제외, 축구장 주차장 추천을 보여줍니다.
- 카드의 추천 이름과 지도 검정 핀이 같은 후보임을 보여줍니다.
- **이곳으로 길안내** → Pleos 내비 목적지 설정을 보여줍니다.
- arrive로 돌아와 주차 완료 → 휴대폰 연결 → 남측 광장 입구 안내 → 합류 확인으로 이어갑니다.

설명 문장: “자리가 없다고 한 번 알려주면, 이미 확인한 곳을 제외하고 다음 주차 후보를 골라줍니다. 주차 후에는 동승자가 먼저 들어간 건물로 안내가 이어집니다.”

## 현재 추천 기준과 제한

- 지원 장소는 오룡관 한 곳, 후보 순서는 주차장 1 → 주차장 2 → 축구장 → 대학원 기숙사입니다.
- 실시간 만차를 자동 감지하지 않습니다. **자리 없어요**는 해당 운전자의 방문 내 제외 의사이며 다른 사용자에게 만차 정보로 전파하지 않습니다.
- 거리·예상 시간·잔여 면수에 따른 순위나 최적화는 구현하지 않았습니다.
- 후보 순서는 주행 경로가 아닙니다. 실제 이용 자격·진입구·일방통행 경로와 추정 좌표는 현장 검증이 필요합니다.
- 추정 좌표를 사용하므로 SDK 경로 요청은 debug 또는 명시적 시연 옵션으로 빌드한 release 에뮬레이터에서만 허용합니다.
- 후보가 모두 소진되면 다시 P1로 돌아가지 않습니다. 현장 안내를 확인하도록 표시하고 종료 확인 창을 제공합니다. 새 방문은 더 보기에서 별도로 시작합니다.
- 공유 웹의 보행 안내·합류 확인 권한 및 API 계약은 변경하지 않았습니다.

## 백엔드 담당자 작업

이번 변경에 추가 API나 마이그레이션은 필요 없습니다. 기존 `REJECT_PARKING`, `parkingId`, `excludedParkingIds`와 버전 고정된 장소 목록을 사용합니다. 추천 표시와 내비 연결 시점을 차량 앱에서 개선했습니다.

여러 장소에서 운영하려면 앱의 장소 선택과 세션 버전별 카탈로그 조회가 선행되어야 합니다. 추후 실제 빈자리 기반 추천을 한다면 출처·관측 시각·신뢰도와 장소 이용 조건이 포함된 별도 데이터 설계가 필요하며, 현재 기능으로 소개하지 않습니다.

## 검증 기록

- debug APK 빌드 성공, 기존 도메인 29개·웹 23개 테스트 통과.
- Pleos Connect 2.1.0에서 P1 → P2 → P3 자동 후보 선택과 추천 화면 유지 확인.
- 프로세스 종료 후 다시 열어도 P3와 P1·P2 제외 상태 유지.
- P3 ‘이곳으로 길안내’ 실행 후 SDK 완료 콜백 및 목적지 대조를 거친 ‘내비 목적지 설정됨’ 확인.
- P4까지 제외한 후 후보 소진 안내, 길안내·주차 완료 버튼 제거, 종료 확인 취소 시 제외 기록 유지 확인.
- 작은 창 레이아웃에서 추천 이름·제외 수·길안내·주차 완료·자리 없어요 표시 확인. 짧은 지도는 여백을 줄이고 추천 라벨을 우선 표시합니다.
- Lint 오류 0개, 기존 경고 6개. 기존 방문 데이터는 검사 전후 동일한 해시로 복원 확인했습니다.
- 검증 캡처: `output/parking-recommendation/` (로컬, Git 제외).

## 제출 전 사용자 확인

1. 설치된 앱에서 추천 화면의 문구와 버튼 순서 확인.
2. 제출 자료에서는 “다음 후보 자동 추천”으로 설명하고 “실시간 빈자리 자동 탐지”로 표현하지 않기.
3. 실제 시연에서 하차·주차 상태를 재현할 방법, 사용 휴대폰, 녹화 길이 결정.
4. 이후 지원서에는 주차 실패 → 다음 후보 선택을 핵심 장면으로, 입구 안내와 합류를 연결된 후속 경험으로 설명.

## 장소에 종속되지 않는 화면

- 앱 헤더는 arrive와 ‘도착 안내’로 구성합니다. 장소명은 ‘더 보기 → 방문 정보’에서 확인하며 서비스 제목으로 사용하지 않습니다.
- 시작 화면은 ‘도착을 준비해요’, 진행 단계는 하차·주차·합류입니다. 실제 첫 안내 지점은 방문 데이터로 별도 표시합니다.
- 주차 추천은 공통 P 아이콘, 추천 주차장 이름, 이번 방문의 제외 수, 남은 다른 후보 수로 구성합니다. P1~P4 고정 코스 타일은 제거했습니다.
- 추천 컴포넌트는 전달받은 방문의 후보 목록을 사용합니다. 후보 개수나 오룡관의 방위·시설 설명을 UI 문구로 가정하지 않습니다.
- 운전자 지도는 추천 주차장을 검정 P, 다른 후보를 흰색 P, 제외한 곳을 ×로 구분합니다. 실제 지명은 지도 목적지 라벨과 상세 안내에 유지합니다.
- 이는 UI의 일반화이며 여러 장소의 검색·선택·세션 카탈로그 전환 구현은 별도입니다. 현재 연결된 실제 시연 데이터와 서버 계약은 그대로 유지합니다.
