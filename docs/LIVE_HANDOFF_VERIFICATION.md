# 운영 휴대폰 연결·합류 확인 검증

검증일: 2026-11-15 KST. 모의 서버를 사용하지 않고 Pleos 에뮬레이터에 설치된 앱, `https://arrive-api.ikjun.com`, Cloudflare Pages `https://arrive.ikjun.com`을 연결했다.

## 결과

**차량 앱에서 QR 발급 → 운전자 휴대폰 화면 연결 → 합류 확인 → 차량과 동승자 상태 반영이 운영 환경에서 통과했다.** 이전의 DB 마이그레이션 미적용으로 인한 기능 차단은 이번 실제 API 흐름에서 재현되지 않았다.

| 확인 항목 | 관찰 결과 |
| --- | --- |
| 새 방문 생성 | 차량 앱에서 동승자 QR 생성, 운영 웹에서 조회 |
| 하차·주차 진행 | 시작 → 하차 확인 → 주차 완료를 앱에서 수행. 서버 주차 단계 revision=4 |
| 운전자 연결 | 주차 완료 후 운전자 QR 자동 표시. 조회용 QR과 다른 handoff 토큰, 운영 웹 주소 확인 |
| 휴대폰 안내 | 390×844 Chromium에서 입구 지도·남측 광장 쪽 입구·합류 확인 버튼 표시 |
| 동승자 권한 | 조회 링크에는 합류 버튼 없음. 동일 공유 토큰으로 합류 POST를 시도하면 인증 거부, 방문 단계/revision 유지 |

| 새로고침 | 같은 탭에서 휴대폰 연결과 완료 상태 복원, 완료 버튼 숨김, URL fragment 제거 확인 |

| 동승자 동기화 | 기존 조회 링크도 HTTP 200, REUNITED / revision=5와 완료 화면 표시 |
| 지도·오류 | 휴대폰 화면 지도 타일 로드 확인. 정상 휴대폰 합류/재조회/새로고침에서 브라우저 오류·경고 0개. 권한 거부 시험의 실패 응답은 의도한 결과 |

## 검증 범위와 정리

- 실제 휴대폰 하드웨어 대신 모바일 크기의 Chromium을 사용했다. QR은 실제 차량 화면 이미지를 해독해 같은 URL을 열었다. 실물 휴대폰 카메라, Safari, 외부 지도 앱 전환은 이번 검사에 포함하지 않았다.
- 차량은 정차한 Pleos 에뮬레이터다. 실제 사람의 하차·주차·보행을 검증한 것이 아니다. 내비 화면에서 앱으로 직접 복귀해 진행했으며, 이번 기록을 내비 자동 복귀 검증으로 계산하지 않는다.
- 네트워크 응답 유실을 이번 운영 검사에서 강제로 만들지는 않았다. 성공 요청을 동일 키/본문으로 재전송해 중복 처리 방지만 검증했다.
- 사용자의 기존 방문 설정은 테스트 전에 별도 보존했다. 종료 후 암호화된 방문 스냅샷을 그대로 복원하고 SHA-256 일치를 확인했다.
- 새 테스트 방문 1건은 완료 상태로 두었으며 만료 예정은 **2026-11-16 19:23 KST**다. 기존 방문이나 공유 토큰을 폐기하지 않았다.
- 운영 코드·DB·배포 설정 수정은 하지 않았다. 테스트 방문 상태만 변경했고 검증 브라우저를 닫았다. 토큰과 QR 원문은 문서/공개 저장소에 포함하지 않는다.
